# ModMind 新手教程：从一句话到第一个 Minecraft Mod

> 本教程面向第一次使用 ModMind、没有 Minecraft Mod 开发经验的用户。你将从零创建一个“星辉矿物”Mod，完成 AI 制作、构建、游戏测试和成品导出。

## 最终效果

完成本教程后，你会得到一个可以放入 Minecraft 的 Mod。它包含：

- 一种会发光的“星辉矿石”；
- 对应的矿石掉落物和方块；
- 一套基础工具；
- 矿石的世界生成规则；
- 合成配方、名称和基础纹理；
- 可以安装到游戏中的 Mod JAR 文件。

## 开始前的准备

开始前，请确认：

1. 已经安装并启动 ModMind；
2. 电脑可以正常联网；
3. 磁盘中留有足够空间，用于下载 Java、Gradle 和 Minecraft 测试文件；
4. 如果使用 ModMind 托管的 AI 服务，已经连接账号；如果使用本机 Agent，已经在设置中完成配置。

你不需要提前安装 Java、Gradle，也不需要会写 Java 代码。第一次构建和启动游戏时，ModMind 会按需准备所需组件。

## 第一步：新建 Mod 项目

在项目首页点击 **新建项目**，然后按下面的方式填写：

| 设置项 | 本教程选择 | 说明 |
| --- | --- | --- |
| 项目名称 | 星辉矿物 | 显示在 ModMind 中的项目名称 |
| 项目类型 | 自制 Mod | 用于制作独立 Mod |
| 游戏平台 | Java 版 | 本教程以 Java 版为例 |
| 加载器 | Fabric | 适合完成第一次练习 |
| Minecraft 版本 | 选择一个稳定版本 | 应与你计划游玩的版本一致 |

确认后点击 **创建项目**。ModMind 会创建完整的工程结构并打开创作工作台。

加载器和 Minecraft 版本在开发过程中不能随意混用。例如，为 Fabric 制作的 Mod 不能直接当作 Forge Mod 安装。如果你是第一次制作，按照本教程的选择完成整个流程即可。

## 第二步：告诉 AI 你想做什么

进入项目后，你会看到创作输入框。把下面这段需求粘贴进去：

```text
请为这个 Mod 添加一种“星辉矿石”。

要求：
1. 矿石生成在主世界地下，数量比钻石稍多；
2. 矿石方块会发出柔和的光，至少需要铁镐挖掘；
3. 挖掘后掉落“星辉矿物”，受时运和精准采集影响；
4. 使用星辉矿物制作一套剑、镐、斧、锹和锄；
5. 工具强度略高于铁制工具，但低于钻石工具；
6. 补全中文和英文名称、合成配方、模型及基础纹理；
7. 完成后检查注册、资源引用和构建结果。
```

点击发送按钮后，ModMind 会读取当前项目、制定修改计划，并创建需要的代码和资源文件。制作过程中不要重复发送同一个需求；如果任务耗时较长，可以先查看状态区域中的当前步骤。

### 怎样让需求更准确

一个容易执行的需求通常包含四类信息：

- **要做什么：** 矿石、物品、方块、生物还是玩法系统；
- **怎样出现：** 生成位置、获取方式、合成方式和前置条件；
- **怎样表现：** 名称、纹理、模型、音效、粒子和发光效果；
- **怎样平衡：** 稀有度、伤害、耐久、冷却和掉落数量。

不要只写“做一个厉害的矿石”。“厉害”没有明确标准，AI 需要猜测你的意图。你可以写成：“生成数量比钻石稍多，工具强于铁但弱于钻石”，这样结果更容易符合预期。

## 第三步：检查 AI 的制作结果

任务结束后，先不要急着进入游戏。检查工作台中的结果摘要，重点确认：

1. 任务状态是否显示完成；
2. 是否列出了本次新增或修改的文件；
3. 自动构建是否通过；
4. 是否存在警告或需要手动确认的内容。

自动验收可以发现编译错误、缺失的资源引用和部分注册问题，但它不能代替实际玩法测试。矿石是否容易找到、工具是否过强、纹理是否协调，仍然需要进入游戏判断。

> **图片 05：AI 任务完成状态**  
> 建议截图：显示任务完成、文件修改摘要和自动验收结果。  
> 建议标注：`制作结果`、`修改文件`、`自动验收`。

如果结果与预期不同，不需要重新创建项目。直接在同一个工作台追加一条具体要求，例如：

```text
把星辉矿石的生成数量降低约三分之一，并把发光等级调整为 8。其他行为保持不变，修改后重新构建验证。
```

每次只调整一组相关内容，之后更容易判断是哪次修改带来了变化。

## 第四步：构建项目

点击 **检查并构建**。ModMind 会使用项目自带的 Gradle Wrapper 编译代码，并生成 Mod JAR。

第一次构建可能比之后更久，因为需要下载对应版本的 Java、Gradle 组件和项目依赖。请保持网络连接，不要在下载过程中强制关闭应用。

构建完成后，应当看到成功状态和生成的成品。如果构建失败，可以先点击 **AI 修复**，让 AI 根据真实的构建错误修改项目并重新验证。

> 建议截图：构建状态为成功，并显示通过项、输出位置或“进入游戏测试”按钮。  
> 建议标注：`构建成功`、`进入游戏测试`。

## 第五步：进入 Minecraft 测试

点击 **进入游戏测试**，或从侧边栏打开 **游戏测试**。

第一次使用测试功能时，先点击 **准备实例**。ModMind 会按需准备 Minecraft、Java 和加载器。准备完成后：

1. 设置测试用户名；
2. 根据电脑内存选择最大内存，通常 4 GB 足够完成基础测试；
3. 点击 **构建并同步**，确保实例使用最新的 Mod；
4. 点击 **启动测试**。

> **图片 07：Minecraft 测试页面**  
> 建议截图：完整展示“准备实例”“构建并同步”“启动测试”、用户名和最大内存。  
> 建议标注：按照实际点击顺序标记 `1`、`2`、`3`。

进入游戏后，建议创建一个创造模式测试世界，并逐项检查：

- 创造模式物品栏中能否找到星辉矿石和工具；
- 放置后的矿石是否正常显示并发光；
- 生存模式下能否使用铁镐挖掘；
- 普通挖掘、时运和精准采集的掉落是否正确；
- 工具的伤害、速度和耐久是否符合预期；
- 合成配方是否可以正常使用；
- 新世界的地下是否会生成星辉矿石。

世界生成内容通常需要在新生成的区块中检查。旧存档已经探索过的区域不会因为安装 Mod 而重新生成矿石。

## 第六步：把问题交给 AI 修复

如果测试时出现问题，记录你看到的现象，然后回到创作工作台描述问题。描述越具体，修复越快。

例如，纹理显示为紫黑方块时，可以写：

```text
进入游戏后，“星辉矿石”显示为紫黑色缺失纹理方块。请检查方块模型、物品模型、纹理路径和命名空间，修复后重新构建。
```

如果游戏直接崩溃，请保留测试页面中的运行日志和崩溃信息。检测到运行期崩溃时，可以使用 **AI 修复并重启**。不要只写“游戏打不开”，应尽量说明：

- 在哪个操作之后发生；
- 是构建失败、启动失败还是进入世界后崩溃；
- 是否每次都能复现；
- 最近一次修改了什么。

> **图片 09：运行期错误与 AI 修复**  
> 建议截图：测试页面中的崩溃摘要和“AI 修复并重启”按钮。  
> 建议标注：`错误摘要`、`AI 修复并重启`。

修复完成后，再执行一次 **构建并同步**，然后重新进入游戏验证。只有问题在游戏中确实消失，才算完成修复。

## 第七步：导出 Mod

确认构建通过、游戏测试正常后，返回创作工作台，点击 **导出成品**。在专业模式中，对应按钮可能显示为 **导出 Mod JAR**。

选择保存位置后，你会得到一个 `.jar` 文件。这个文件就是可以分发和安装的 Mod 成品。

安装时应确保：

- Minecraft 版本与项目版本一致；
- 使用相同的加载器，例如 Fabric；
- 已安装项目需要的前置模组；
- 不要把源码压缩包当作 Mod JAR 放入 `mods` 文件夹。

## 常见问题

### 第一次构建为什么很慢？

ModMind 需要下载与项目版本匹配的运行环境和依赖。之后再次构建通常会复用本地缓存，速度会明显提升。

### 构建通过，为什么还要进游戏测试？

构建通过只能说明代码和资源满足编译要求，不能证明玩法、数值、显示和世界生成完全正确。

### 修改后游戏里为什么还是旧效果？

先停止正在运行的游戏，再点击 **构建并同步**，然后重新启动测试。对于世界生成修改，还应前往新生成的区块验证。

### AI 修改后效果更差了怎么办？

打开版本记录或项目快照，恢复到修改前状态。恢复前应先确认当前有用的修改是否需要保留。

### 怎样获得更好看的纹理？

可以使用 ModMind 的图像工坊生成或编辑纹理，也可以导入自己绘制的 PNG。纹理风格、分辨率和透明区域应与 Minecraft 资源要求保持一致。

### 如何提交无法自行解决的问题？

在设置中导出诊断日志，并同时提供：ModMind 版本、Minecraft 版本、加载器、复现步骤和问题截图。诊断日志不会包含已经保存的 API Key 或 Token。

## 下一步可以做什么

完成第一个 Mod 后，可以继续尝试：

- 为星辉工具增加右键技能和冷却时间；
- 使用图像工坊重新设计整套纹理；
- 使用 Blockbench 制作带有立体结构的方块或物品模型；
- 添加盔甲、成就、音效和粒子效果；
- 为项目添加前置或联动模组；
- 发布到 Modrinth、CurseForge 或 GitHub Releases。

第一次作品不需要追求功能很多。先完成“提出需求、构建、测试、修复、导出”这一整套流程，再逐步增加内容，会比一次塞入大量功能更容易得到稳定结果。
